# 04 · 实现路线图（P0–P6）

原则：每期独立可验收、可上 dev 环境；后端先行一小步（接口+测试），前端跟进；每完成一个验收项 commit+push（遵守仓库自动推送规则）；工程过程写 `docs/worklog/`。

## P0 · 设计系统落地（前端基础，1 期）

- [ ] `design-system.css` 以设计稿 tokens 为准合并；全局引入
- [ ] `ds/atoms`：Icon/WPill/WDot/WCard/WStat 对齐设计稿（Pill nowrap、mono 数字）
- [ ] `ds/shell`：Sidebar（导航+用户卡+引擎状态）/Topbar（风控胶囊+⌘K+Pilot AI 按钮）/PageShell
- [ ] CommandPalette（⌘K：页面导航+交易对搜索）
- **验收**：所有既有页面套新 shell 无回归；`npm run build` 通过；无硬编码色值（grep 检查）

## P1 · 主控台重构 + 决策流式（1-2 期）

- 后端：`decision.progress/complete` WS 事件（3.3）；`GET /api/decisions/{id}` 详情
- 前端：DecisionCard 3 变体 + StreamingDecision（WS 驱动）+ HaltBanner + AnimatedNumber + 权益曲线交互
- HALTED 全局联动五件套（横幅/hero/曲线变色/事件流红条/顶栏胶囊）
- **验收**：testnet 触发一次完整决策链，前端实时看到逐段点亮；模拟熔断联动全部生效；后端测试全绿

## P2 · 行情 + 手动下单（1-2 期）

- 后端：market 域 4 接口 + `market.{symbol}` WS 代理；orders precheck/下单/sltp（3.2）
- 前端：行情页（lightweight-charts + 盘口/成交 + AI 解读条）+ OrderTicket
- **验收**：testnet 手动下一单全链路（预检→下单→持仓出现→SL/TP 标线上图）；HALTED 时非 reduce-only 被拒；守卫预检与实际下单判定一致（同一服务，写等价性测试）

## P3 · Pilot AI 对话（1 期）

- 后端：agent 域 SSE + 工具白名单 + pending action confirm（3.4）
- 前端：ChatDrawer（⌘J、工具轨迹、流式、快捷问题、应用修改按钮）
- **验收**：四个预设问题真实走通（查持仓/解释决策/风险敞口/收紧风控-需确认）；Agent 无法绕过 confirm 直改配置（写守卫测试）

## P4 · 设置 + RBAC + 后台（1-2 期）

- 后端：settings 三组接口（密钥加密+脱敏）；RBAC role+权限依赖项+2FA；admin 扩展（3.6/3.7）
- 前端：设置四分区；登录 2FA；后台三分区（含权限矩阵页）
- **验收**：viewer 账户调交易接口返回 403；API Key 全链路无明文回显；权限矩阵与端点守卫一致（对照测试）；pending 用户批准流走通

## P5 · 策略实验室（1-2 期）

- 后端：lab 域接口 + 影子执行调度 + 灰度自动回滚（3.5）
- 前端：实验室页（流水线/候选卡/对比/门槛/历史）
- **验收**：候选影子运行 24h 产生对比数据；门槛校验在服务端生效（前端绕不过）；模拟回撤触发自动回滚 + 事件通知

## P6 · 绩效归因（1 期）

- 后端：performance 三接口（3.8）
- 前端：绩效页（指标磁贴/对比曲线/月度零轴柱图/归因切换）
- **验收**：指标与 DB 交易记录对账一致（写对账测试）

## 里程碑依赖

```
P0 ─► P1 ─► P2 ─► P3
        └──► P4 ─► P5
                   P6（P2 后随时可做）
```

## 每期收口检查单

1. `make test` 全绿 + 新增功能测试覆盖（守卫/权限类必须有拒绝路径测试）
2. `make lint && make fmt`；前端 `npm run build`
3. 视觉走查对照设计稿（tokens、色彩纪律、mono 数字、空/异常态）
4. `docs/worklog/` 记录 + commit + push（CI 自动部署 dev）
5. 涉及 schema 变更：alembic migration（`-c src/db/alembic.ini`），不手改表
