# 05 · AI 协作手册（在仓库内驱动 Claude 实现）

## 会话启动模板

每次新会话第一条消息：

```
读取 CLAUDE.md、docs/project.md、.claude/memory/ 全部记忆文件，
再读取 design/handoff/ 全部交付文档。
当前做路线图 P{N} 的「{验收项}」。先给实现方案（涉及的文件/表/接口/测试），
我确认后再动手。完成后跑测试、commit、push。
```

要点：**先方案后编码**；一次会话只做一个验收项，避免上下文稀释。

## 设计还原的提问方式

- ✅ "按 handoff/02 的 P3 行情页规格实现 OrderTicket，样式 token 见 design/ui_kits/web_app/components/trade_panel.jsx，翻译成 TSX + CSS 变量"
- ❌ "把 trade_panel.jsx 复制过来改改"（原型代码不能直接进生产）

让 AI 打开设计稿源文件对照实现是有效的——jsx 里的布局/间距/颜色变量就是规格本身。

## 必须让 AI 遵守的红线（来自仓库规范，重申）

1. env 黑白名单：只碰 `example.env`；真实密钥永不读写
2. 所有内部 import `src.` 开头；依赖用 `uv add`，禁 pip install
3. schema 变更走 alembic migration，不手改
4. 守卫/权限/幂等逻辑必须有**拒绝路径**测试，不只测 happy path
5. 完成即 commit+push，不询问；工程过程写 `docs/worklog/`
6. 硬风控规则不可被 LLM/Agent 绕过——任何"AI 修改配置"都走 pending action + 人工确认

## 常用验收提示词

- 视觉走查：`对照 design/ui_kits/web_app/ 截图逐项检查：token 使用、Pill 不换行、数字 mono、涨跌色纪律、HALTED 联动五件套`
- 守卫等价性：`写测试证明 /api/orders/precheck 与 POST /api/orders 对同一 payload 的守卫判定完全一致`
- 权限矩阵：`对照 handoff/03 §3.7 权限映射，为每个端点写 viewer/trader/admin 三角色的 200/403 参数化测试`
- 对账：`写测试：performance summary 的净收益 = trades 表逐笔求和，误差为 0`
