## 为什么不新建表

盘点时发现 `strategy_scores` 表已在 `init_schema` migration 里（"有表无逻辑"），字段：
`win_rate / pnl_sum / max_drawdown / sharpe / false_breakout_rate / regime_fit_score / sample_count`，
unique key = `(account_id, strategy_mode, symbol, regime, window)`。这正是评分器要写的结构。
故删掉初版新建的 `models/strategy_score.py`，复用现有表——符合"从现有代码学习"+ 避免重复造数据层。

## 关键设计点

- **纯计算先行**：`compute_strategy_metrics(trades)` 无状态、duck-typed（只读 pnl/pnl_pct/exit_reason/closed_at），不碰 DB，覆盖空集/单笔/多笔/夏普边界（<2 笔或零方差返 None）/止损率。
- **分组维度**：(strategy_mode, symbol, regime)，None 维度用 `"unknown"` 占位（现有表维度 non-null），不丢老数据。
- **trading_mode 隔离**：评分窗口按 trading_mode 过滤，testnet/mainnet 互不串。
- **调度低频**：`STRATEGY_SCORING_INTERVAL_HOURS=24`，对历史已平仓交易聚合，不影响实时交易链路。
- **API**：`GET /api/strategy-scores?window=30d`（登录）+ `POST /generate`（admin），前端 dashboard 加桌面表格 + 移动卡片（沿用既有样式类）。
