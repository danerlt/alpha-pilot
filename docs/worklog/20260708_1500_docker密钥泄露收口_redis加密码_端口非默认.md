# Docker 密钥泄露收口：Redis 加密码 + 端口非默认 + 密钥全挪 gitignored env

日期：2026-07-08
分支：dev
背景：一次 Docker 变动把**真实 PG 密码 + 端口**写进被 git 跟踪的 compose 文件并提交到
**公开 GitHub 仓库**，裸奔一段时间。老板已 revert + force-push 回退 HEAD。

> ⚠️ force-push 只移走 HEAD，GitHub 对旧 commit SHA 仍可能缓存一段时间（fork/PR/事件流亦留存）。
> **泄露的密码必须视为已永久泄露，一律轮换**，端口改非默认为纵深防御。

## 做了什么

统一原则：**被 git 跟踪的 compose 一律不写死密钥，改用 `${VAR:?}` 引用 gitignored 的 env；
密钥/端口只存 `envs/*.env`（app 栈）和 `docker/.env`（中间件），二者都被 `.gitignore` 忽略。**

| 文件 | 改动 |
|------|------|
| `docker/docker-compose.middleware.yml` | PG 密码 `${DB_PASSWORD:?}`（去掉弱默认 `alphapilot`）；**Redis 加 `--requirepass`**（原来无密码！）+ 带密码健康检查；PG/Redis 宿主机端口参数化 `127.0.0.1:${PG_HOST_PORT:-59133}` / `${REDIS_HOST_PORT:-46730}`（非默认，仅回环） |
| `docker-compose.{dev-server,test,prod}.yml` | `DATABASE_URL` 密码改 `${DB_PASSWORD:?}`；`REDIS_URL` 改 `redis://:${REDIS_PASSWORD:?}@ap-redis:6379/{0,1,2}`（连中间件必须带密码，否则连不上） |
| `docker-compose.yml`（泄露根因型：跟踪文件里写死明文 + 端口绑 0.0.0.0） | PG 密码参数化、Redis 加密码、端口改 `127.0.0.1:${...}` 回环 |
| `docker-compose.local.yml` / `docker-compose.dev.yml` | 本机 loopback 栈：DB/Redis 端口补 `127.0.0.1:` 绑定（防同网段暴露）；密码保持本地 throwaway 以不打断 526 绿测 |
| `docker/docker-env.example`（新增，跟踪） | `docker/.env` 模板：`DB_PASSWORD`/`REDIS_PASSWORD`/`PG_HOST_PORT`/`REDIS_HOST_PORT` |
| `example.env` | REDIS_URL 补密码格式说明 `redis://:<pwd>@host:port/db`；PG/Redis 强密码 + docker/.env 提示 |

无 Python 代码改动（`RedisConfig.REDIS_URL` 已支持 `redis://:pwd@` 形式），526 测试不受影响。

## 部署侧关键事实（deploy_common.sh 已确认）

- app 栈 `docker compose --env-file envs/<env>.env up` → `${DB_PASSWORD}`/`${REDIS_PASSWORD}` 从 `envs/<env>.env` 取。
- 中间件 `up` 无 `--env-file` → 变量来自 `docker/.env`（compose 自动加载）。
- 中间件有"健康则不重建"守卫 → 密码/端口变更需**手动 `--force-recreate`**。
- **`POSTGRES_PASSWORD` 仅初始化生效**：ap-postgres 卷已存在 → 必须容器内 `ALTER USER` 手动轮换。

## 服务器收口清单（老板手动执行）

1. 进 ap-postgres 轮换泄露密码：
   `docker exec -it ap-postgres psql -U alphapilot -c "ALTER USER alphapilot PASSWORD '<新强密码>';"`
2. 建 `docker/.env`（server，gitignored）：`cp docker/docker-env.example docker/.env` 填强随机
   `DB_PASSWORD`（= 上一步新密码）/`REDIS_PASSWORD`/`PG_HOST_PORT`/`REDIS_HOST_PORT`。
3. 每个 `envs/{dev,test,prod}.env` 加：`DB_PASSWORD=<同上>`、`REDIS_PASSWORD=<同上>`，
   并把 `REDIS_URL` 改成 `redis://:<REDIS_PASSWORD>@ap-redis:6379/{0,1,2}`。
4. 重建中间件让 Redis 密码/新端口生效：
   `cd docker && docker compose -f docker-compose.middleware.yml up -d --force-recreate`
5. 重新部署 app 栈（push dev 触发，或手动 deploy-dev.sh）。
6. 本地看数据走 SSH 隧道：`ssh -L 15432:127.0.0.1:<PG_HOST_PORT> user@server` → DBeaver 连 `localhost:15432`。

## 验证

- `docker compose -f docker-compose.middleware.yml config`（喂假值）渲染正确：
  PG 密码入环境、`127.0.0.1:59133`、Redis `--requirepass`、健康检查带密码探活、`127.0.0.1:46730`。
- 其余 app 栈语法一致（config 报 env_file 缺失是黑名单文件不在本机，非语法错）。
