# 服务器部署打通 — 共享中间件 + scheduler + CI 测试门禁（2026-06-27）

## TL;DR

老板要"push dev 自动部署到服务器 + 三环境共用一套中间件靠不同库隔离"。落地：
**共享中间件架构** + **补上缺失的 scheduler 进程** + **CI 测试门禁** + **dev/uat/prod → dev/test/prod 理顺**。
全程占位符，**零真实 IP/端口/域名/路径进 git**（敏感值只在 GitHub Secrets + 服务器 envs/）。

## 发现的致命缺口（先于本次需求）

所有应用 compose **只起了 backend(API)，没有 scheduler 进程**——而项目是双进程模型。
后果：部署后策略循环/持仓监控（止损止盈熔断）/异步任务消费/EventShuttle/通知告警/评分/归因 job **全不运行**。
本次一并补齐（每个应用 compose 加 scheduler service）。

## 架构：共享中间件 + 库隔离（采纳老板方案）

```
docker-compose.middleware.yml  （常驻一套）
  ap-postgres → 库 alphapilot_dev / _test / _prod
  ap-redis    → db0=dev db1=test db2=prod
  共享 network: ap-shared (external)

docker-compose.{dev-server,test,prod}.yml  （应用三件套，不含 pg/redis）
  backend(API) + scheduler + frontend，加入 ap-shared 连中间件
```

| 环境 | 分支 | nginx | api/前端口 | database | redis db |
|---|---|---|---|---|---|
| dev | dev | /ap-dev | 8001/3001 | alphapilot_dev | 0 |
| test | test | /ap-test | 8002/3002 | alphapilot_test | 1 |
| prod | main | /ap | 8003/3003 | alphapilot_prod | 2 |

## CI 自动部署 dev 链路（老板核心需求）

`git push origin dev` → GitHub Actions `Deploy Dev`：
1. **test job**：起 PG(5442)/Redis(6389) service → 后端 `uv run pytest` + 前端 `typecheck/test/build`。
2. **deploy job**（needs test）：`_deploy.yml` 用 secrets SSH 进服务器 → `cd <DEPLOY_DIR_DEV> && bash scripts/deploy-dev.sh`。
3. deploy-dev.sh：确保中间件 → 建库兜底 → git pull → 起 backend+scheduler+frontend → 单点迁移 → 健康三检 → 失败回滚。

## 敏感信息处理
