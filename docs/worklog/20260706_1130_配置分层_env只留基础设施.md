# 20260706 配置分层 — env 只留基础设施，业务密钥走前端设置页

## 背景（老板指令）

后端 env 调整为只配置中间件/基础设施（PG、Redis 等），交易所 API Key 与 LLM 配置
在前端设置页配置并保存到数据库。

## 发现并修复一个真缺陷

排查中发现 **DB runtime 配置链路是断的**：`RuntimeConfigManager.refresh_from_db` 把
overrides 存进 manager，但没有任何代码把它写回 `get_settings()` 单例（全仓无人消费
`get_overrides()`）——前端设置页 / runtime API 写入 DB 的配置**实际从未生效**，
所有装配点（adapter/LLM/守卫参数）一直读的是 env 值。

**修复**：`apply_runtime_settings_refresh` 现在把 overrides setattr 回
`get_app_config()` 单例（TRADING_MODE 转 enum），并保留 binance client 缓存清理。
新增回归测试断言「DB 写入 → settings 单例生效」。

## 加载链路（新增 `refresh_runtime_settings_safe`，容错：DB 不可用只 warning）

| 时点 | 位置 | 说明 |
|------|------|------|
| api 启动 | `app.py` lifespan（admin bootstrap 之后） | 启动即加载 DB 配置 |
| scheduler 启动 | `scripts/start_scheduler.py` | 同上 |
| 每个策略周期 | `new_strategy_pipeline_job` 开头 | 前端改配置最迟一个周期（默认 15 分钟）在 scheduler 生效，无需重启 |
| settings PUT 后 | `AppSettingsService._refresh`（已有） | api 当前 worker 即时生效 |

**已知限制**（记录）：api 多 worker 时，非处理 PUT 请求的 worker 要等自身下次启动才拿到新值
（本地 dev 单 worker 无感；后续可用 Redis Pub/Sub 广播刷新，未排期）。

## 配置分层（example.env + CLAUDE.md 已同步）

- **env 必配**：ENVIRONMENT、PG_*/DATABASE_URL、REDIS_URL、`APP_AUTH_SECRET_KEY`、
  **`APP_CONFIG_MASTER_KEY`（解密 DB 业务密钥的根，必须且只能在 env）**、调度参数、
  DEFAULT_ADMIN_*（可选）、TRADING_MODE（DB runtime.trading_mode 可覆盖）
- **env 仅 fallback（日常留空）**：BINANCE_API_KEY/SECRET、LLM_API_KEY/BASE_URL/MODEL
  —— 推荐走前端【设置→交易所连接 / AI 模型】，`PUT /api/settings/{exchange,llm}`
  Fernet 加密入库；**DB 值优先于 env**
- 风控 MAX_* 为初始 fallback，DB（runtime config / Agent 提议+确认）可覆盖
- 无 Key 时安全降级：LLM 回退 Mock（恒 HOLD 不误下单）；行情公共端点无 Key 可用

## 验证

- 全量回归 **690 passed + 2 skipped**，ruff 全绿
- 新增用例：DB overrides 写回 settings 单例断言（risk/binance/llm 三类键）+ DB 不可用启动不炸

## 对老板的操作影响

- `envs/<env>.env` 与根 `.env` 里的 BINANCE_*/LLM_* 可以删掉（保留也不冲突，DB 配置后被覆盖）
- 首次使用：登录前端 → 设置→交易所连接 填 Key → 测试连接（看权限清单，提现必须关）→ 保存；
  设置→AI 模型 同理
