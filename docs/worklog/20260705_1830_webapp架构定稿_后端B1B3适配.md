# 20260705 webapp 前端架构定稿 — 后端 B1-B3 适配

## 背景

前端会话产出并经老板批准了 [`docs/webapp前端架构.md`](../webapp前端架构.md)（webapp 定为唯一前端主线，数据层升级 S1-S4），其中 §3 是后端配合清单。老板指令全自动适配。B1 的导出脚本（`backend/scripts/export_openapi.py`）前端会话已交付，本次完成其余增量。计划：`docs/superpowers/plans/2026-07-05-webapp-arch-backend-b1-b3.md`。

## 做了什么

### B1 · OpenAPI 契约固化

1. **operation_id 稳定化**：`src/app.py` 新增 `_use_route_names_as_operation_ids`（operation_id 缺省=endpoint 函数名），health 双路径显式给 id；新增 `tests/api/test_openapi_contract.py` 守护「非空 + 全局唯一」——前端 openapi-typescript 生成的函数名从此不随路径漂移。
2. **核心 15 端点显式响应模型**：新增 5 个 read 模型文件（`schemas/{execution,market,strategy,risk,system}_read.py`），positions / trades / account / decisions 列表与详情 / risk-events / market 三接口 / orders 两接口 / risk/state / auth login·me·logout / admin roles 全部挂 `response_model=Response[...]`——生成的 TS 类型里 data 不再是 unknown。字段与既有返回 dict 逐 key 一致（97 个 API 测试兜底零回归）。`precheck` 的 `pass` 关键字用 `Field(alias="pass")` 处理。
3. 重导 `docs/api/openapi.json`（43 paths，含本次新增端点），前端 `npm run gen:api` 即可拿到新类型。

### B2 · WS 事件面补齐（S2 依赖）

4. 新事件契约：`risk.state`（state/day_loss_pct/positions_pct/regime）与 `account.snapshot`（权益快照全字段）入 `EVENT_TYPE_REGISTRY`。
5. `RiskStateService`（`src/services/risk/risk_state.py`）：聚合 kill_switch+熔断 → HALTED；日亏超熔断上限一半 → WARN；仓位占比 = Σ开仓市值/总权益；regime 取最新快照。发布点：pause / resume / resolve-breaker（commands 控制器，与业务写同事务）+ position_monitor 熔断首次触发。
6. `AccountStateService.sync_snapshot` 支持 outbox 注入，快照落库即发 `account.snapshot`（策略管道已接线）——前端权益曲线实时生长的数据源。
7. 新端点 `GET /api/risk/state`（登录可见）：前端断线或初载时主动拉取的兜底口。

### B3 · 认证升级（S3 依赖）

8. login 下发 **httpOnly cookie**（`ap_token`，SameSite=Lax，uat/prod 加 Secure，有效期与 JWT 一致），与 Bearer 头并存不破坏既有调用方；`get_current_user` 增加 cookie 回退（优先 Bearer）。
9. `POST /api/auth/logout` 清 cookie（不要求有效 token，过期也能登出）。
10. `GET /api/admin/roles`：权限矩阵下发（`src/services/system/permissions.py` 常量表，与设计稿 admin.jsx PERMS 逐项对齐；`role_aliases: {"user": "trader"}` 做 P4 RBAC 前的过渡映射）——前端 `usePermission()` 唯一数据源；登录即可读（viewer 也要知道自己不能做什么），端点级强制仍 require_admin。
