# 人工覆盖 AI 守卫 — 后端落地（2026-07-08）

> 来源：`IMPLEMENTATION_PLAN.md`「人工覆盖 AI 守卫」章节，后端任务 1.1 / 1.2 / 2.1 后端子任务。
> 核心诉求：手动下单守卫失败时，允许经二次确认「强行下单」，但物理约束与「OPEN_LONG 缺 SL」永不可覆盖，判定权全在服务端。

## 做了什么

### 任务 1.1 — override_checks 入参 + 服务端 allowlist 逐项裁决（⚠高危）
- `src/schemas/manual_order.py::ManualOrderCreate` 新增 `override_checks: list[str] = Field(default_factory=list)`（wire snake_case）。
- `src/services/execution/manual_trade.py` 新增模块级权威分类常量（服务端唯一真相）：
  - `NON_OVERRIDABLE = {balance, position_exists, close_quantity, duplicate_position}`
  - `OVERRIDABLE_BREAKER = {kill_switch, daily_loss, consecutive_losses}`
  - `OVERRIDABLE_SOFT = {review, chaotic_regime, rr_ratio, sl_distance, position_size, single_risk, strategy_enabled}`
- `place_order` 把原「`verdict != PASS` 取首个失败项即 `RiskRejectedException`」改为逐项裁决：
  - **铁律先判**：`side=="BUY"` 且 `sl is None` → 一律拒，override 无效（独立硬拒分支，先于物理裁决）。
  - 收集所有 `passed=False` 的 check：`check in NON_OVERRIDABLE` → 永远拒；`check in override_checks 且 check in (BREAKER|SOFT)` → 放行该项；否则拒。
  - 物理安全只信服务端 allowlist 交集，不信前端。全部失败项被合法覆盖或本就 PASS → 走既有 executor 路径不变。
- 幂等短路（`order_crud.get_by_trace_id`）保持不变。

### 任务 1.2 — 覆盖分级审计（⚠高危）
- `_audit` 增参 `verdict / overridden / failed_detail`，裁决阶段就地收集透传，不二次查询。
- action 分级：无覆盖 `manual_order`；仅软项 `manual_order_override`；含熔断项 `manual_order_override_breaker` 并打 `logger.warning`。
- `AuditLog.before_json = {verdict, failed:[{check,note,severity}]}`；`after_json = {...原 detail, override_checks, operator_user_id}`。
- `ManualOverride.reason` 带覆盖 key 列表，`action` 与审计对齐。复用现成 `AuditLog` + `ManualOverride`，**无 Alembic 迁移**。

### 任务 2.1 后端子任务 — precheck 下发 category
- `PrecheckOutcome.to_dict` 每项 check 补 `category`，经模块级 `_category_for()` 由**同一组常量**派生：physical / breaker / soft。
- `src/schemas/execution_read.py::GuardCheckItem` 新增 `category: str`。
- 重导 `docs/api/openapi.json`（override_checks 入参 + category 出参一次合并导出，diff 仅 14 增 1 删）。

## 为什么这么做
- 「人工决策 > AI 守卫」但物理铁律不可越——判定权收口在 `place_order` 服务端 allowlist，前端只读展示，即便前端漏判把物理项塞进 override_checks，后端交集仍拒。
- 全程**不改 `ExecutionGuard.check/evaluate/precheck`**，AI 调度链路零影响。
- 覆盖为**单次放行**：熔断项覆盖不写 KillSwitch、不解除熔断，下一单仍会被拦；`resolve-breaker`/KillSwitch 解除仍走独立 admin 命令。
