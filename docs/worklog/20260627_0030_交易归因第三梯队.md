# 交易归因分析（PRD 8.1.3 + 12.1 / V0.3）— 第三梯队（2026-06-27）

## TL;DR

第三梯队首做 V0.3 里**风险最低**的一块——交易归因。**只读历史交易做事后拆解，零交易决策影响**（区别于参数优化/Shadow 那些会影响下单的高风险块）。同样是接通"有表无逻辑"骨架表 `trade_attributions`。

**结果：TDD 4 阶段全绿，新增 19 个测试，全量 526 passed + 2 skipped，ruff 全清，前端 build+typecheck 通过，零新表/零 migration。**

## 为什么先做归因（V0.3 里最低风险）

- PRD 8.1.3 明确要"按 币种/时间段/触发类型/因子 拆解盈亏"；PRD 12.1 要"每一笔交易必须可解释"。
- 纯读历史 `trades` + 写解释，**不参与任何交易决策**——不像参数优化/Shadow/自动回滚那样直接改下单行为。
- `trade_attributions` 骨架表已就绪（trade_id 非空 + narrative + 维度字段），逐笔形态。

## 两件事（一次交付）

1. **逐笔归因**（写 `trade_attributions`）：每笔已平仓交易生成中文叙述
   （"BTCUSDT 在 trending_up 行情下，breakout 策略止盈，盈利 +X (+Y%)，持仓 Zh"）+ 维度标签 → 服务 PRD 12.1 可解释性。
2. **聚合拆解**（读时纯算，不持久化）：按 symbol/exit_reason/regime/time_bucket 拆解盈亏（pnl_sum/count/win_rate，按盈亏降序）→ 服务 PRD 8.1.3。

## 关键设计点

- **纯计算先行**：3 个无状态纯函数，duck-typed，覆盖时段分桶/中文叙述（盈亏正负、退出原因中文化）/聚合拆解（空集/多维度/降序）。
- **time_bucket**：UTC 小时分 4 时段（night/morning/afternoon/evening）作"时间段"维度。
- **逐笔 upsert**：按 trade_id 幂等，重跑归因更新而非插重复。
- **summary_only**：REST summary 端点只算不写表，避免读操作产生副作用。
- **trading_mode 隔离**：归因窗口按 trading_mode 过滤。
- **因子维度（by_factors）留 None**：因子库未实现，留后续。
- 调度复用 `STRATEGY_SCORING_INTERVAL_HOURS`（归因与评分同为日级低频）。
