# 20260628 build-once / deploy-many 重构 + dev 服务器部署全自动打通

## 做了什么

1. **部署范式重构(build-once / deploy-many)**:开发/构建/部署三类目录分离;compose 由 `build:` 改 `image:`;
   deploy 脚本拆成"构建目录 fetch+build → 部署目录 image 起栈";镜像按 git SHA 构建一次,
   同一 commit 沿 `dev→test→main` 复用同一镜像晋升,环境差异只在 env。
   - backend/scheduler 共用 `alphapilot-backend:<sha>`(ROOT_PATH 运行时区分,真 build-once);
   - frontend 因 `basePath` 由 build-arg 在 `npm run build` 构建期烘焙,无法跨环境复用 →
     按环境构建 `alphapilot-frontend:<sha>-<env>`(设计例外)。
   - 公共逻辑收敛到 `scripts/lib/deploy_common.sh`(`run_deploy()`),三入口脚本仅设变量后调用;
     全逻辑封装在函数内,规避"运行中脚本被 checkout 覆盖"问题。
2. **服务器部署落地(dev)**:建共享中间件、构建目录 `alpha-pilot-build`、瘦部署目录 `alpha-pilot-deploy/{dev,test,prod,middleware}`;
   清理 3 个月前旧 `ap-dev` 容器(保留数据卷)。
3. **专用部署用户 `deployer`**:仅 docker 组(非 root);两把 key(部署 key=Actions→服务器;deployer GitHub key=服务器→GitHub 拉代码,加仓库 Deploy keys)。
4. **GitHub 全自动部署打通**:push dev → 测试门禁 → deployer SSH → 构建目录 fetch+build-once → 部署 dev。`DEPLOY_DIR_*` 指向构建目录。
5. **Node 20→24(LTS)**:Dockerfile.frontend + 三 workflow setup-node。
6. **域名 HTTPS**:`https://www.danerlt.top/ap-dev`;续期过期的 letsencrypt 证书并补 `/etc/cron.d/certbot` 自动续期(原先无任何自动续期才过期)。
7. **凭据接入**:dev `envs/dev.env` 填真实 LLM key + Binance testnet key + 管理员;均生效。
8. **文档**:新增 build-once spec;更新 runbook(deployer/secrets/deploy-key 全流程 + 排错)、deploy-ci.md。

## 为什么做

老板要求"部署目录不存源码、镜像单独构建",并明确"构建一次、多环境部署同一镜像、dev 领先"——
即标准的 build-once / deploy-many 不可变镜像模型。原范式(服务器 git pull + 本地 `--build`,部署目录=源码)与此冲突,故重构。

## 过程中修的真 bug

- 中间件每次部署被重建(compose 文件路径变 → config 哈希变):改为"已健康则不动"。
- `No module named src`:alembic/scheduler 用 console_script/`python scripts/x.py` 不会自动把 `/app` 入 sys.path
  (uvicorn 会)。修 `upgrade_db.py` 注入 PYTHONPATH + Dockerfile.backend 加 `ENV PYTHONPATH=/app`。
- 建库竞态(pg_isready 过但未可查询):等真正可查询 + 幂等建库容错。
- scheduler 健康误报:`logs --tail=30` 在长跑容器里滚出启动标记 → 改判"容器 running 且非重启"。
- 单测 `test_upgrade_db` 断言精确 kwargs 过时:改为校验命令+check+env.PYTHONPATH。
- Binance `-2015`:最终确认是 testnet key 需从 testnet.binance.vision 生成(换 key 后 10000 USDT 通过);
  排查中验证了 python-binance 1.0.x 在请求时才切 testnet 端点(`API_URL` 属性是误导)。
- certbot 续期"假性卡住":非交互续期有最长 ~8min 随机延迟,`--no-random-sleep-on-renew` 解决;
  另避免 `pkill -f certbot` 误杀含 "certbot" 字样的自身 shell。
