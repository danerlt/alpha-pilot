# 20260705 handoff 后端 P2 — 行情 REST + 手动下单

## 背景与口径决策（重要）

handoff/03 §3.1 行情契约含资金费率/OI/标记价（USDT-M 合约概念），而仓库 V0.1 交易链路是 Binance **Spot 现货做多**。老板未明确拍板迁合约，本期采用可逆的中间路线：

- **交易链路维持现货不动**（守卫/执行/监控零语义变化）
- 行情页装饰性指标（mark price / funding rate / OI）走 Binance USDT-M **公共**行情端点（无需密钥），不可用时字段为 null，前端降级显示
- 该决策被适配层（`get_futures_metrics`）隔离，未来若整体迁 USDT-M 只需替换 adapter

实现计划：`docs/superpowers/plans/2026-07-05-handoff-backend-p2-market-and-manual-orders.md`。盘口/逐笔 WS 代理拆到 P2b 另做。

## 做了什么

### 行情域（handoff 3.1，新 controller 域 `api/v1/market/`）

1. 适配层扩展：`Ticker24h` / `FuturesMetrics` 类型 + `get_ticker_24h` / `get_futures_metrics`（基类非抽象默认 None，不破坏既有 stub；失败静默返 None 只记 warning）
2. `GET /api/market/klines`：DB（candles 表）新鲜够量直接走库，否则交易所直取透传（不落库，避开 market_data 的 delete-and-insert 幂等窗口），交易所失败降级返 DB 存量
3. `GET /api/market/ticker`：24h 统计 + 合约公共指标合并输出
4. `GET /api/market/symbols`：symbol_config 启用清单 × 实时行情 × 是否持仓 × 最新 regime；单 symbol 行情失败只置空该行

### 手动下单（handoff 3.2，`api/v1/execution/orders.py`）

5. **守卫重构**：`ExecutionGuard.evaluate()` 跑全部 10 条规则产出逐项 `GuardCheckResult`（不短路/不写审计），`check()` 重建为 evaluate + `derive_verdict`（首个未过项定裁决），未通过项 note 与旧版 reason **逐字一致**，21 个既有守卫测试零改动全绿——预检与实盘判定同源（roadmap P2 验收：等价性参数化测试）
6. `POST /api/orders/precheck`：组装真实上下文（现价/可用余额/ATR/regime/日亏），kill_switch 永远是第一项；**HALTED 时仅放行 SELL+reduce_only**；SELL 校验持仓存在 + V0.1 不支持部分平仓
7. `POST /api/orders`：服务端**重跑**守卫（不信任预检）；幂等 trace_id = SHA256(`manual:{user_id}:{client_order_id}`)[:32]（重复提交返回既有订单）；BUY 走 `OrderExecutor.manual_open`（从 open_long 提取 `_execute_open` 共用内核，事件照发），SELL 走 `close_long`（新增可选 trace_id 参数）；写 audit_logs + `manual.override` 事件；LIMIT 明确返回"暂不支持"（V0.1 市价 + 监控式 SL/TP）
8. `PATCH /api/positions/{id}/sltp`：方向校验（多头 SL<现价、TP>现价）+ SL 距离 ATR 区间（与守卫规则 7 同逻辑）+ 审计 + `position.updated` 事件

### 附带修正

- `strategy_mode` 白名单增加 `"manual"`（source=manual 的人工单需要）
- 发现并修正 `PositionStatus.OPEN.value` 是小写 `"open"`，新代码统一用枚举值而非硬编码字符串
