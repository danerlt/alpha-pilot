# AlphaPilot 本地启动指南（完整功能验证）

> 目标：在本机从零把 **api + scheduler + 前端** 三个进程跑起来，验证完整功能。
> 跑起来之后验什么 → 见 [`docs/testnet验收手册.md`](testnet验收手册.md)（逐项打勾清单）。
> 本指南的坑位提示来自 2026-07-06 的本地 e2e 验收实录（`docs/worklog/20260706_1540_本地e2e验收报告.md`）。

## 0. 前置（一次性）

| 依赖 | 要求 |
|------|------|
| Python | 3.12（`backend/.python-version` 固定） |
| uv | `D:\programs\uv\bin\uv.exe` |
| Node | webapp 需要（`cd webapp && npm install` 首次执行） |
| Docker | 跑 PostgreSQL 16 + Redis 7 |

```powershell
# 首次克隆后初始化
cd backend
uv venv --seed --python 3.12
uv sync --extra dev

cd ..\webapp
npm install
```

## 1. 启动依赖栈（PG 5442 + Redis 6389）

```powershell
make deps-up
# 或（已有容器时）
docker start alpha-pilot-postgres-1 alpha-pilot-redis-1
```

> 机器重启后容器不会自动起，api 启动报 `Connection refused ... port 5442` 就是忘了这步。

## 2. 配置 `.env`（只需基础设施）

**配置分层原则**：env 只放基础设施；交易所 Key / LLM Key / Telegram 都在**前端设置页**配（加密入库，DB 值优先于 env，重启自动加载）。

从 `example.env` 拷贝出根 `.env`，需要动的只有这些：

```env
ENVIRONMENT=local
TRADING_MODE=testnet

# 数据库/Redis（本机默认端口即可）
PG_HOST=localhost
PG_PORT=5442
REDIS_URL=redis://localhost:6389/0

# 两个必填密钥（一次性生成，务必保存好 —— MASTER_KEY 是解密 DB 内业务密钥的根）
# 生成命令：
#   cd backend
#   uv run python -c "import secrets; print(secrets.token_hex(32))"                              → APP_AUTH_SECRET_KEY
#   uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"  → APP_CONFIG_MASTER_KEY
APP_AUTH_SECRET_KEY=<上面生成的 hex>
APP_CONFIG_MASTER_KEY=<上面生成的 Fernet key>

# 默认管理员（首启自动创建，登录用）
DEFAULT_ADMIN_EMAIL=admin@example.com
DEFAULT_ADMIN_USERNAME=admin
DEFAULT_ADMIN_PASSWORD=<自己设一个强密码>

# ── 验证期提速（验完改回）─────────────────────────────
STRATEGY_LOOP_INTERVAL_MINUTES=2     # 正式 15；验证期 2 分钟一轮决策
PIPELINE_SYMBOLS=BTCUSDT,ETHUSDT

# BINANCE_* / LLM_* / NOTIFY_TELEGRAM_* 全部留空 —— 走前端设置页
```

> **挂代理的机器注意**：如果本机有全局代理（VPN），给 `.env` 或系统环境加
> `NO_PROXY=localhost,127.0.0.1`，否则本地进程间调用会被代理劫持（e2e 实测踩坑）。

## 3. 初始化数据库

```powershell
make upgrade-db
# 等价于: cd backend; uv run python scripts/upgrade_db.py
```

首启 api 时会自动创建默认管理员 + 默认风控 Profile，无需手动建数据。

## 4. 启动三个进程（三个终端）

```powershell
# 终端 1 — API (:8000)
make dev-backend
# 等价于: cd backend; uv run python scripts/start_api.py

# 终端 2 — Scheduler（策略循环/持仓监控/影子执行/事件搬运/通知）
cd backend
uv run python scripts/start_scheduler.py

# 终端 3 — 前端 (:5174，同源代理到 :8000，cookie 直通)
cd webapp
npm run dev:real
```

**启动健康自检**（看日志确认三行）：

| 进程 | 应看到 |
|------|--------|
| api | `runtime settings loaded from DB (api_startup)` + `Application startup complete` |
| scheduler | `runtime settings loaded from DB (scheduler_startup)` + `APScheduler started` + `EventShuttle daemon started`（**不能**有 `Exception in thread event-shuttle`） |
| 前端 | Vite ready → 打开 http://localhost:5174 |

或直接探活：

```powershell
curl http://localhost:8000/api/health
# data.status=ok; runtime_credentials 里 binance/llm 初始为 configured:false（还没配 Key，正常）
```

## 5. 首次配置（全部在前端完成）

1. 打开 http://localhost:5174 → 用 `DEFAULT_ADMIN_EMAIL/PASSWORD` 登录
2. **设置 → 交易所连接**：填 Binance **testnet** Key/Secret →「测试连接」
   - 必须看到权限清单 `读取✓ / 交易✓ / 提现✗`（提现开着会出强警告，请去交易所关掉）
   - 保存后页面只显示 `****尾4位`；testnet Key 在 https://testnet.binance.vision 申请，水龙头充值 USDT
3. **设置 → AI 模型**：填 DeepSeek（或任意 OpenAI 协议端点）Key →「测试连接」→ 保存
   - 不配也能跑：LLM 自动回退 Mock，决策恒 HOLD，绝不误下单
4. （可选）**设置 → 通知**：Telegram bot token + chat_id，熔断类告警会推送
5. 配完**无需重启**：api 当前进程即时生效；scheduler 最迟一个策略周期（步骤 2 设的 2 分钟）自动加载

## 6. 验证完整功能

从这里开始照 [`docs/testnet验收手册.md`](testnet验收手册.md) 逐项打勾：

- **2 分钟内**：主控台 AI 决策卡逐段点亮（快照→推理→守卫→裁决→执行）
- 行情页：K线/盘口/逐笔实时跳动（真连 Binance）
- 行情页手动下一单：预检逐项 PASS → 下单 → 持仓出现 → K线 SL/TP 标线
- 风控页暂停引擎 → 全站 HALTED 联动 → 只允许 reduce-only → 恢复
- ⌘J 打开 Pilot AI：问持仓/风险/让它收紧风控（走确认流）
- 实验室提交候选 → 启动影子 → 看对比数据积累
- 后台建 viewer 账号验证权限、开 2FA 验证二段式登录

## 7. 常见问题速查

| 现象 | 原因/处理 |
|------|----------|
| api 启动 `Connection refused :5442` | 依赖容器没起 → 步骤 1 |
| 启动报 `InsecureSecretError` | `.env` 两个 APP_* 密钥没填或是弱值 → 步骤 2 生成 |
| `make upgrade-db` 报 URL 解析错 | 拉最新代码（2026-07-06 已修 env.py 的 db_uri 回退） |
| 决策卡不点亮 | scheduler 没起 / LLM 没配（Mock 恒 HOLD 也应点亮到"裁决"）/ 看 scheduler 日志 `strategy_pipeline summary` |
| 决策每轮报 `get_balance` 错 | Binance Key 没配或无效 → 前端设置页配置并测试连接 |
| 行情盘口没数据 | 拉最新代码（testnet WS 域名 2026-07-06 修复）；确认代理可出海 |
| 事件流/实时推送不动 | scheduler 日志确认 `EventShuttle daemon started` 且无异常（2026-07-06 修复过两处） |
| 本地请求诡异 503 | 全局代理劫持 localhost → `NO_PROXY=localhost,127.0.0.1` |
| 配置改了 scheduler 没生效 | 等一个策略周期（自动刷新），或重启 scheduler |

## 8. 关停

```powershell
# 三个终端 Ctrl+C 即可；容器可留着下次直接用
docker stop alpha-pilot-postgres-1 alpha-pilot-redis-1   # 需要时再停
```
